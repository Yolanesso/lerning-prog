# Структура базы данных для MVP

В текущем варианте база хранит:

- пользователей;
- языки программирования;
- курсы по этим языкам;
- уроки;
- задания;
- информацию о прохождении уроков.

---

## Общая логика

Структура обучения выглядит так:

**programming_language → course → lesson → exercise**

Отдельно хранится пользовательская часть:

**user → lesson_completions**

Это значит, что одна часть базы отвечает за **обучающий контент**, а другая — за **действия и прогресс пользователя**.

---

## 1. `users`

Таблица `users` хранит **пользователей приложения**.

### Основные поля

- `id` — уникальный идентификатор пользователя;
- `email` — адрес электронной почты;
- `username` — логин или никнейм;
- `password_hash` — пароль в зашифрованном виде;
- `created_at` — дата и время регистрации.

### Что это означает

Каждая строка в этой таблице — это **один пользователь**.

Примеры:

- пользователь с почтой `ivan@example.com`;
- пользователь с почтой `anna@example.com`.

---

## 2. `programming_languages`

Таблица `programming_languages` хранит **языки программирования**, доступные в приложении.

### Основные поля

- `id` — уникальный идентификатор языка;
- `code` — техническое+отображаемое имя языка, например `python`;

### Что это означает

Каждая строка в этой таблице — это **один язык программирования**. (пока их будет три: **java**, **bash**, **python**)

---

## 3. `courses`

Таблица `courses` хранит **курсы обучения**.

### Основные поля

- `id` — уникальный идентификатор курса;
- `language_id` — ссылка на язык программирования, к которому относится курс;
- `title` — название курса;
- `description` — краткое описание курса.

### Что это означает

Каждая строка в этой таблице — это **один курс по конкретному языку**.

Примеры:

- `Python Basics`;
- `Java Basics`;
- `Bash for Beginners`.

### Связь с другими таблицами

Один язык программирования может содержать **много курсов**.

Связь выглядит так:

- `programming_languages.id` → `courses.language_id`

Это означает, что курс всегда принадлежит одному языку.

---

## 4. `lessons`

Таблица `lessons` хранит **уроки внутри курсов**.

### Основные поля

- `id` — уникальный идентификатор урока;
- `course_id` — ссылка на курс, к которому относится урок;
- `title` — название урока;
- `theory` — теория или краткое объяснение темы;
- `sort_order` — порядок урока внутри курса;
- `xp_reward` — количество XP за прохождение урока.

### Что это означает

Каждая строка в этой таблице — это **один урок внутри конкретного курса**.

Примеры уроков для курса `Python Basics`:

- `Variables`;
- `If statements`;
- `Loops`.

### Связь с другими таблицами

Один курс может содержать **много уроков**.

Связь выглядит так:

- `courses.id` → `lessons.course_id`

Это означает, что каждый урок обязательно относится к одному курсу.

---

## 5. `exercises`

Таблица `exercises` хранит **задания внутри уроков**.

### Основные поля

- `id` — уникальный идентификатор задания;
- `lesson_id` — ссылка на урок, к которому относится задание;
- `type` — тип задания (`choice` или `input`);
- `payload` — содержимое вопроса в формате JSON (текст, варианты, правильный ответ);
- `sort_order` — порядок задания внутри урока.

### Что это означает

Каждая строка в этой таблице — это **одно маленькое упражнение** внутри урока.

Поле `payload` — это просто JSON-объект, в котором лежат сам вопрос и ответ. Для `choice` внутри: `title`, `options`, `correctOption`. Для `input` внутри: `title`, `codePrefix`, `placeholder`, `correctAnswer`.

Пример:

- вопрос: `Что выведет: print(2 + 3)?`;
- правильный ответ: `5`.

### Связь с другими таблицами

Один урок может содержать **много заданий**.

Связь выглядит так:

- `lessons.id` → `exercises.lesson_id`

Это означает, что каждое задание обязательно относится к одному уроку.

---

## 6. `lesson_completions`

Таблица `lesson_completions` хранит **факт прохождения уроков пользователями**.

### Основные поля

- `id` — уникальный идентификатор записи;
- `user_id` — ссылка на пользователя;
- `lesson_id` — ссылка на урок;
- `completed_at` — дата и время прохождения;
- `score` — результат прохождения, например 80 или 100.

### Что это означает

Каждая строка в этой таблице — это **один факт завершения урока конкретным пользователем**.

Примеры:

- пользователь Ivan прошёл урок `Variables`;
- пользователь Anna прошёл урок `Loops`.

### Связь с другими таблицами

Таблица связана сразу с двумя сущностями:

- `users.id` → `lesson_completions.user_id`;
- `lessons.id` → `lesson_completions.lesson_id`.

Это означает, что запись о прохождении всегда относится:

- к одному пользователю;
- к одному уроку.

---

## Что есть у пользователя в этой схеме

У пользователя в текущем минимальном варианте есть две части данных.

### 1. Данные аккаунта

Они лежат в таблице `users`:

- почта;
- логин;
- пароль;
- дата регистрации.

### 2. Данные о прохождении уроков

Они лежат в таблице `lesson_completions`:

- какие уроки пользователь уже прошёл;
- когда он их прошёл;
- с каким результатом.

### Чего пока нет

В этой версии пока нет:

- streak;
- achievements;
- leaderboard;
- отдельные попытки по каждому заданию;
- подробная статистика активности.

---

Когда проект станет больше, в базу можно будет добавить новые таблицы, например:

- exercise_attempts;(id, user_id, exercise_id, answer, is_correct, score, submitted_at)
- user_progress;(id,user_id, course_id,completed_lessons, completed_exercised, total_xp, last_lesson_id)
- daily_activity.(id, user_id, activity_date, lessons_completed, exercises_completed, xp_earned)

Зачем они нужны:
- exercise_attempts — чтобы видеть попытки по заданиям (ну это думаю не оч нужно)
- user_progress — чтобы быстро показывать общий прогресс
- daily_activity — чтобы потом сделать streak и дневную статистику
